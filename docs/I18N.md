# 多言語対応 (i18n) 設計メモ

英語圏プレイヤー向けに UI を日本語 / 英語の二言語対応にしたときの設計と運用メモ。

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/shared/I18n.luau` | 文言テーブル (`ja` / `en`)、ロケール解決、`t()` / `levelTitle()` / `levelDesc()` / `reading()` |
| `src/shared/Romaji.luau` | かな → ローマ字 (ヘボン式ベース)。英語UIで読みを併記するために使う |
| `src/shared/GameConfig.luau` | 級ごとの英語表記 (`en = { label, desc }`) と JLPT の目安 (`jlpt`) |
| `src/client/KanjiKombatClient.client.luau` | 言語の自動判定・🌐 切り替え・全UIの再描画 |
| `src/server/Modules/StatsService.luau` | 表示言語の保存 (`profile.locale`) とリーダーボード名 (勝数 / Wins) |
| `src/server/Modules/MatchService.luau` | サーバーからのメッセージを「キー + パラメータ」で送る |

## 言語の決まり方

1. 起動時に `Player.LocaleId` (無ければ `LocalizationService.RobloxLocaleId`) を読み、
   `ja*` なら **日本語**、それ以外は **英語** にする (`I18n.localeFromId`)。
2. `GetProfile` で保存済みの手動設定 (`profile.locale`) が返ってきたら、そちらを優先する。
3. ロビー右上の **🌐 ボタン**でいつでも切り替え可能。手動で選ぶと `setLocale` (source = "manual") が
   サーバーに送られ `KK_Profile_v1` に保存される。次回以降は手順 2 で復元される。
4. 端末の言語設定が変わると (`Player.LocaleId` の変更)、自動判定モードのときだけ追従する。

> Roblox の `LocalizationService` / 翻訳ポータルによる自動翻訳は「インスタンスに置いた静的な文字列」が対象で、
> RemoteEvent で送る動的な文字列 (問題文・トースト・結果) は翻訳されない。
> そのため本プロジェクトでは **文言テーブルを持つ共有モジュール** で自前対応している。

## 文言キー

`src/shared/I18n.luau` の `STRINGS` に `key = { ja = "...", en = "..." }` の形で定義する。
プレースホルダは `{name}` 形式で、`I18n.t("profileStats", { wins = 3, losses = 1, streak = 2 })` のように渡す。

```lua
I18n.setLocale("en")
I18n.t("battleButton")                        --> "Find a Match"
I18n.t("answerWrong", { answer = "kyoushuu" }) --> "Missed — the answer is “kyoushuu”"
I18n.levelTitle("K10")                        --> "Level 10" (ja なら "10級")
I18n.levelDesc("K10")                         --> "Grade 1 (elementary) · ≈ JLPT N5"
```

* **サーバーは文章を送らない**: `send(player, "toast", { key = "toastSearching", args = { level = levelKey } })`
  のようにキーとパラメータだけを送り、クライアントが自分の言語で組み立てる。
  これにより同じサーバーに日本語・英語のプレイヤーが混在しても正しく表示される。
* `args` の中の `level` (級キー) はクライアント側で `levelFull()` により翻訳される。

### 文言を追加するとき

1. `STRINGS` に `ja` / `en` を追加 (片方だけだと `tools/test_luau.py` が失敗する)。
2. クライアントは `I18n.t("key")` で参照し、`retranslate()` に登録する
   (登録しないと 🌐 切り替え時にその場で更新されない)。
3. `python3 tools/test_luau.py` を実行 — 「コードから参照されているのに未定義」も
   「定義されているのに未使用」も検出される。

## 級の英語表記

`GameConfig.LEVELS` の各要素に以下を持たせている。

| フィールド | 例 | 説明 |
| --- | --- | --- |
| `label` / `desc` | `10級` / `小学校1年生修了程度` | 日本語UI (漢検の表記そのまま) |
| `en.label` | `Level 10` | 英語UI。準2級 = `Level Pre-2`、準1級 = `Level Pre-1` |
| `en.desc` | `Grade 1 (elementary)` | 学年・学校段階の目安 |
| `jlpt` | `≈ JLPT N5` | 英語UIでのみ併記する JLPT の目安 |

JLPT の目安は級別漢字表の累計字数 (N5≈100 / N4≈300 / N3≈650 / N2≈1000 / N1≈2000字) からの
ざっくりした対応で、**漢検とは別制度**なので英語UIでは `≈` を付けて「目安」と明示している。

## ローマ字 (Romaji.luau)

* ヘボン式ベース。長音は母音を重ねる wāpuro 方式 (`きょうしゅう` → `kyoushuu`, `らーめん` → `raamen`)。
* 促音は次の子音を重ねる (`がっこう` → `gakkou`)、`っち` は `t` (`まっちゃ` → `matcha`)。
* `ん` は母音・や行の前で `n'` (`しんよう` → `shin'you`)。
* 選択肢 4 つは `Romaji.convertMany()` を使う。`じ` / `ぢ` のように同じ表記になる場合は
  自動で別表記 (`ji` / `di`) に切り替える。全12,000問で重複ゼロを `tools/test_luau.py` が検証する。

## 表示の使い分け

| 画面 | 日本語UI | 英語UI |
| --- | --- | --- |
| 選択肢 | `きょうしゅう` | `kyoushuu` (大) + `きょうしゅう` (小) |
| 正解・不正解 | `正解！ 与ダメージ 20` / `ざんねん… 正解は「きょうしゅう」` | `Correct! +20 damage` / `Missed — the answer is “kyoushuu / きょうしゅう”` |
| レベルカード | `10級` / `小学校1年生修了程度` / `レート 1000` | `Level 10` / `Grade 1 (elementary) · ≈ JLPT N5` / `Rating 1000` |
| ロビー看板 (3D) | `KANJI KOMBAT / 漢字コンバット` (両言語併記で固定) | 同左 |
